## Corrected release blockers

| Problem | Root cause | Final behaviour |
| --- | --- | --- |
| A newly uploaded invoice could remain `NO MATCH` | Upload refreshed the workspace but did not rerun the existing comparison workflow | A successful upload now runs comparison first, selects the latest invoice and refreshes mapped findings automatically |
| `Carried Out Full Service` did not map | Generic PDF tables labelled the operation as a part before ontology matching | Extraction recognises carried-out service descriptions as service operations |
| `Fit Track Rod Ends` did not map | The description was classified from the table section instead of its action wording | Descriptions beginning with `Fit` are classified as labour operations |
| `Waste Oil and Filter` did not map | The synonym was present, but the extracted item kind was incompatible with the disposal ontology item | Waste + oil + filter wording is classified as disposal before matching |
| Missing monetary values appeared as `£0.00` | The UI money formatter treated `null` as numeric zero | Missing values now render as an em dash |
| Payable price and challenge amount could be confused | One workflow label did not clearly distinguish the two values | The review wording explicitly identifies the supported net price and challenge amount |

## Business-rule verification

| Rule | Evidence |
| --- | --- |
| Same repair descriptions normalise together | Oil-disposal, oil-filter, air-filter and service wording variants map to their canonical items |
| P90 uses earlier invoices only | Evidence drawers list the exact earlier invoice numbers, descriptions and prices; `currentInvoiceExcluded` is true |
| P90 method | Interpolated percentile (`PERCENTILE.INC`) |
| Challenge threshold | 5% mode produced 30 exception lines; 10% mode produced 29, with the £5 minimum retained |
| Governed price evidence | Ontology price and eligible historical-claim median remain visible separately from uploaded-invoice P90 |
| Final supported price | Uses the higher reliable evidence ceiling, capped at the billed price; the LLM never invents a price |
| Manual governance | Low-confidence/unmatched cases require review; high-confidence mappings are auto-accepted |
| Knowledge graph | Repairer-to-canonical-item challenge relationships, invoice counts, line counts and values are populated from benchmark exceptions |

## Non-blocking notes

- Vite reports a bundle-size advisory (approximately 647 KB before gzip). The build succeeds and the tested runtime is unaffected.
- Python dependencies emit deprecation notices only; the full suite passes.
- Generated variant invoices do not contain a repairer name, so their graph node is correctly labelled `Unknown repairer`. Real invoices with supplier data retain the supplier name.
- Azure Document Intelligence, Gemini and company-laptop network policy require the client's own credentials/environment and cannot be certified from this local machine. Native-text PDF processing does not require OCR and was fully verified.
